Homun provenance
Source: https://github.com/NousResearch/hermes-agent
Commit: c9dca726514b709cf6e677d236a79fc8d0627f37
native_prompt.py adapts execution guidance from agent/prompt_builder.py.
native_turn.py and application/agent_native.py reimplement canonical assistant/tool
history, request projection and persist-before-execute logic described in
agent/conversation_loop.py, agent/turn_request_assembly.py and agent/turn_tool_round.py.
Homun changes: scoped materials/tools, contribution-mediated questions, one pending
call per durable advance, existing authority/budget/review controls. No upstream
runtime dependency. This notice covers the derived portions, not all Homun code.

agent_control_history.py adapts interruption checkpoints and user correction
placement from agent/interrupt_control.py and conversation_loop.py. Homun uses
durable epochs/leases and explicit unknown outcomes in its own SQLite workflow.

context_plan.py derives rough multilingual token estimation and closed-exchange
context planning from agent/model_metadata.py and agent/context_compressor.py.
context_summary.py adapts the structured checkpoint prompt from the latter.
Homun preserves canonical history and stores separate hash-validated projections.

models/native_errors.py adapts the failure taxonomy of agent/error_classifier.py
and the Retry-After/jittered base-2 backoff of agent/retry_utils.py and
agent/turn_recovery.py (compute_error_backoff): statuses and well-known body
patterns map to a smaller Homun code set, raw provider bodies are never stored,
and provider-reported usage is carried on the typed failure when present.
application/agent_recovery.py adapts the retry placement of
agent/turn_api_error.py (three total attempts per phase, waits outside any
lease/transaction, corrections surviving backoff) onto Homun durable runs;
application/agent_run_failures.py keeps the shared terminal-failure fence.

Overflow recovery: application/agent_overflow.py and the forced context plan adapt
agent/turn_overflow.py at the same pinned Hermes commit. Homun retains explicit
window/output pins and durable authority/budget/control checks.

Tool registry: tools/registry.py and application/agent_tool_registry.py adapt
the single-entry schema/handler/toolset design of Hermes tools/registry.py at
the same pinned commit. Homun builds immutable per-run contracts and validates
manifest hashes before model/tool IO; discovery grants no additional authority.

application/agent_mcp.py adapts namespacing and bounded hash-suffixed wire names
from tools/mcp_tool_schema.py at the pinned commit. Homun hashes original server
identity and tool name to prevent sanitized-name collisions. Native integration
uses Homun approvals and durable receipts, without an upstream runtime.

application/agent_results.py adapts complete-result storage and 40/60 head/tail
previews from tools/tool_result_storage.py and tools/tool_output_truncate.py at
the pinned commit. Homun uses private per-run SQLite JSON, SHA-256 references,
scoped paged retrieval and retained error flags instead of host spill paths.

tools/search.py derives BM25 scoring, rarest-query-token admission and minimum
answerable-term coverage from tools/tool_search_catalog.py at the pinned commit.
Homun adds deterministic name tie-breaking and Unicode tokenization, and indexes
only the approved run registry. English stemming and deferred bridge not included.

application/agent_tool_bridge.py derives progressive disclosure and the
search/describe/call bridge from tools/tool_search.py and tool_search_validation.py
at the pinned commit. Homun defers selected MCP schemas, pins bridge contracts
per run, keeps canonical wrapper IDs, and resolves each action through its own
approval/receipt flow. Native ordered rounds replace opaque bridge batches.

models/repetition.py derives conservative repetition detection from
agent/repetition_guard.py at the pinned commit. Homun retains the minimum
length/repeat/dominance thresholds and distinct-line safeguard, but counts only
nonoverlapping windows to avoid false positives on a single long separator.
Native responses fail with a typed nonretryable code before history/tool dispatch,
while provider-reported usage remains charged.

Text continuation: models/truncation.py and application/agent_continuation*.py
adapt visible-fragment nudges and bounded continuation from agent/turn_truncation.py
and conversation_loop.py. Homun durably accepts at most three nudges, retains raw
canonical fragments, and joins exact text without Hermes's inserted newlines to
preserve mid-token URLs/JSON. A version-pinned validated 64k native decision
contract is shared by creation and crash replay; approvals, controls and budgets
remain authoritative. Incomplete tool arguments are never dispatched.

application/agent_liveness.py derives the short trailing-continue-intent detector
and bounded action nudge from agent/agent_runtime_helpers.py and
agent/turn_final_response.py at the pinned commit. Homun adds the observed Italian
shape, conservative quote/excerpt exclusions, durable counters and human-control
fences. After two ineffective nudges it reports a typed stall instead of publishing
another promise as a completed deliverable. This is not semantic task verification.

execution/file_match.py derives the ordered fuzzy replacement chain from
tools/fuzzy_match.py at the pinned commit. execution/file_syntax.py derives the
lint-delta rule (new errors only; JSON/TOML fail closed) from
tools/file_operations_lint.py. Homun keeps directory-descriptor confinement,
exact human approval before any write, and does not run Hermes LSP or shell
linters. Language-server diagnostics stay unavailable and are reported as such.

execution/docker.py derives container hardening, hash-based ownership and
reconnection patterns from tools/environments/docker.py at the pinned commit.
Homun uses a separate container per immutable job, offline SHA256-pinned images,
private workspaces, bounded CLI capture and durable exclusive dispatch intents.
This backend is not yet exposed to agents; Hermes is not a runtime dependency.
