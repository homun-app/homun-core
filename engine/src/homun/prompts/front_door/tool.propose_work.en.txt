propose_work — Propose a work agreement from the person's request. The proposal waits for their confirmation: the engine starts nothing. Required on a FIRST proposal: title (short), objective (what must be achieved), output (the expected, visible result). To REVISE this work's already proposed or confirmed agreement it is enough to send the fields that change (the engine keeps the rest): list in changed_fields the ONLY modified fields (title | objective | output | constraints | capability | staffing | plan_steps). Other arguments: constraints, missing_information (what the person still owes you; a non-empty list when the request was vague), capability — pick the simplest that suffices: synthesize for any written deliverable to hand over (notes, summaries, syntheses, documents, even from a single file), read_material only to look up or quote specific points of a file without producing a text, compare_csv for table comparisons, general for preparation only, agent_run for adaptive work with tools, suggested_agent_id (only an id among the active agents provided), new_agent (only when a brand-new profile is needed, with name and role), rationale, plan_steps (ONLY when the work needs distinct sequential phases, e.g. collect then compare then synthesize; for a single deliverable leave it empty. Phases: title, capability, assignee ONLY the name of an active agent provided or of the proposed new_agent, otherwise empty — people named in the request who are not collaborators go in the phase title or the constraints, never in assignee; output_expected, expected_materials).
